# 결정 원장

프로젝트의 중요한 설계 결정을 시간순으로 기록한다.

---

## 2026-09-25 — 10분 Continuous Loop 도입

상태: 도입

발견: 하루 한 번 실행으로는 “AI가 계속 생각하면서 프로젝트를 진화시키는” 목적을 충족하기 어렵다.

결정: 10분마다 시장 조사와 프로젝트 개선 사고를 수행하는 Continuous Loop 구조로 전환한다.

이유: 변화 감지와 개선 사이의 지연을 줄이고, 시장 리서치와 프로젝트 자체의 발전을 하나의 지속 루프로 만들기 위해서다.

기대효과: 새로운 시장 변화와 프로젝트 개선 아이디어를 더 빠르게 발견할 수 있다.

위험: API 호출 비용 증가, 의미 없는 반복, GitHub Actions 지연 및 동시 쓰기 충돌 가능성이 있다.

대응: 저비용 Scout 모델, 의미 있는 변화 Gate, 단일 writer concurrency, 변경 수 제한을 사용한다.

## 2026-09-25 — 결정·아이디어·실험 기록을 코드와 동급 자산으로 취급

상태: 도입

발견: AI가 스스로 바꾸기만 하면 시간이 지나면서 “왜 이렇게 됐는지”를 잃는다.

결정: DECISIONS, IDEAS, EXPERIMENTS, HELP_NEEDED, CHANGELOG_AI를 장기 기억으로 유지한다.

이유: 성공뿐 아니라 보류·실패·폐기 이유도 다음 AI 판단의 입력으로 사용하기 위해서다.

## 2026-09-25 — 무제한 자기수정 대신 위험 기반 자동수정

상태: 도입

발견: AI가 워크플로·권한·비밀키·자기 안전장치까지 자동으로 바꾸면 작은 오류가 프로젝트 전체를 망가뜨릴 수 있다.

결정: 낮은/중간 위험 변경은 자동 적용하고, 높은 위험 변경은 제안으로만 기록한다.

이유: 자율성과 장기 안정성을 동시에 확보하기 위해서다.


## 2026-09-25 — 국내시장 분봉 거래대금 중심 Market Tape 도입

상태: 도입

발견: 뉴스 기반 시장 리서치만으로는 사용자가 중요하게 보는 종가베팅·눌림·동조수급을 객관적으로 판단하기 어렵다.

결정: 국내시장은 별도의 Market Tape 계층을 두고 거래대금 상위 Universe와 1분봉을 분석한다.

이유: 같은 상승이라도 거래대금이 부족하면 신뢰도가 낮을 수 있으며, 여러 관련 종목에 같은 시간대 자금이 들어오는 흐름은 개별 뉴스와 다른 시장 정보를 준다.

기대효과: “무슨 장세인지”를 기사 제목이 아니라 실제 돈의 흐름으로 설명할 수 있다.

위험: 분봉 데이터 호출량, 데이터 누락, 분 거래대금 근사 오차가 있다.

대응: 상위 Universe만 상세 조회하고, 데이터 품질과 근사 여부를 결과에 남긴다.

## 2026-09-25 — 종가베팅/눌림 통계는 전체 표본을 누적

상태: 도입

발견: 상승에 성공한 차트만 사후적으로 보면 실제 승률과 위험을 과대평가할 수 있다.

결정: 조건을 충족한 전체 이벤트를 저장하고 다음 날/1·3·5일 MFE·MAE를 사후평가한다.

이유: “평균적으로 몇 % 빠지고 반등하는가” 같은 질문에 생존자 편향 없이 답하기 위해서다.

검증 기준: 최소 표본 수 이전에는 통계 결론을 내리지 않고 표본 축적 중으로 표시한다.


## 2026-09-25 — 전체시장 폭과 주도주 Market Tape를 분리

상태: 도입

발견: 거래대금 상위 일부 종목만 보고 전체 시장이 강하거나 약하다고 일반화하면 왜곡될 수 있다.

결정: KOSPI·KOSDAQ 전체 상승/보합/하락 종목 수와 지수 흐름은 별도 전체시장 계층으로 읽고, 거래대금 상위 종목의 1분봉은 주도 자금의 위치와 속도를 읽는 상세 Market Tape로 분리한다.

이유: “지수는 강한데 실제 상승 종목은 적은 장”, “지수는 보합인데 신규주·특정 그룹으로 자금이 집중되는 장”처럼 서로 다른 장세를 구분하기 위해서다.

## 2026-09-25 — 분봉 거래대금은 절대값과 상대값을 동시에 연구

상태: 도입

결정: 각 종목에 대해 평소 분봉 거래대금 대비 burst뿐 아니라 5억·10억·20억·50억원 이상 1분봉의 횟수와 최대 1분 거래대금을 함께 저장한다.

이유: 같은 3배 burst라도 평소 유동성이 매우 작은 종목과 실제 수십억원이 체결되는 종목의 의미가 다르기 때문이다.

추가 결정: 신규상장주 집단에서는 10억·20억원 이상 분봉이 총 몇 회, 몇 종목에서 발생했는지도 집계한다.

## 2026-09-25 — 동조 수급은 시간 동기화를 요구

상태: 도입

결정: 같은 그룹·섹터 종목이 단순히 같은 날 상승한 것만으로 동조 수급으로 분류하지 않는다. 기본값으로 3분 범위 안에서 여러 종목의 가격 상승과 거래대금 burst가 함께 발생해야 강한 동조로 기록한다.

이유: 사용자가 관찰하려는 것은 이름이 비슷한 종목의 동반 상승이 아니라 같은 시간대에 실제 자금이 여러 종목으로 들어오는 장면이기 때문이다.

## 2026-09-25 — 종가베팅 연구 Universe 확대와 결과 확률화

상태: 도입

결정: 장중 상세 분석은 비용을 고려해 상위 일부 종목을 깊게 보되, 장 마감 종가베팅 연구는 거래대금 상위 50개를 기본 Universe로 확대한다.

결정: 중앙 MFE/MAE뿐 아니라 다음 날 +3/+5% MFE 도달 비율, -3/-5% MAE 역행 비율, 갭상승 비율을 함께 계산한다.

이유: 평균값 하나보다 실제 분포와 실패 빈도를 보는 것이 종가베팅의 위험을 이해하는 데 더 적합하다.

## 2026-09-25 — 눌림 반등의 이전 하락폭을 역으로 측정

상태: 도입

결정: 눌림 표본의 1·3·5거래일 MFE/MAE를 누적하고, 5거래일 안에 +5% 또는 +10% MFE가 발생한 표본만 다시 모아 그 전에 실제로 얼마나 눌렸는지 중앙값과 분위수를 계산한다.

이유: “평균적으로 어느 정도 하락한 뒤 반등이 나오는가”를 성공 차트 몇 개의 인상으로 판단하지 않고 전체 코호트에서 역으로 측정하기 위해서다.

## 2026-09-25 — 장세 조건을 종가베팅 이벤트와 함께 보존

상태: 도입

결정: 각 종가베팅 연구 이벤트에 KOSPI/KOSDAQ 등락률·상승종목 비율, 거래대금 Top10 집중도, 신규주 burst 강도, 동시 그룹수급 여부를 함께 저장한다.

이유: 앞으로 같은 차트 패턴이라도 “넓은 상승장”, “소수 종목 집중장”, “신규주 장세”, “그룹주 장세”에서 결과가 어떻게 달라지는지 조건부 통계를 만들기 위해서다.

## 2026-09-25 — 마지막 유효 장세와 실행 상태 분리

상태: 도입

결정: 장외 시간 실행이나 일시적인 데이터 부재가 마지막 유효 장세를 덮어쓰지 않도록 `latest.json`, `runtime.json`, `dry_run_latest.json`을 분리한다.

이유: 장이 끝난 뒤 웹 대시보드가 “데이터 없음”으로 바뀌어 당일 장세 기록을 잃는 문제와 dry-run 합성 데이터가 실전 상태를 오염시키는 문제를 동시에 막기 위해서다.
