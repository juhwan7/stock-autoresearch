# 6분 관측 큐 · 1시간 AI 감독

## 목적

GitHub Actions가 6분마다 OpenAI API를 직접 호출하지 않는다.

대신 6분마다 AI 없는 객관적 관측을 저장하고, ChatGPT 예약 작업이 관측 10개를 모아 한 번에 판단한다.

6분 GitHub 관측 × 10 → recent.json 누적 → ChatGPT 1시간 감독 → 중복 제거·지속성 판단 → 필요한 변경만 적용 → 다음 6분 관측에서 검증

이 구조의 목적은 API Key 없이도 6분 해상도의 상태 기록을 유지하면서, 일시적인 오류 하나에 AI가 과잉 반응하는 것을 줄이는 것이다.

## 6분 GitHub 관측이 하는 일

.github/workflows/연속연구와진화.yml은 6분마다 다음을 수행한다.

- Toss snapshot을 사용할 수 있으면 가져온다.\n- 네이버 금융의 공개 지수 보조값과 Google News 다중 주제 RSS에서 시장·뉴스 단서를 수집한다.\n- 반도체·AI, 로봇·전력·방산, 바이오·2차전지·자동차, 매크로, 정책·공급망 등 1시간 심층 리서치용 handoff query를 함께 남긴다.\n- Health Watchdog을 실행한다.
- Python compile, pytest, git diff --check 결과를 기록한다.
- 직전 GitHub Actions 결과를 확인한다.
- 최근 커밋에서 바뀐 파일을 기록한다.
- 미처리 사용자 피드백 개수를 기록한다.
- 관측 결과를 data/supervisor/queue/YYYY-MM-DD.jsonl에 추가한다.
- 최근 120개 관측을 data/supervisor/recent.json에 유지한다.

이 단계에서는 OpenAI API를 호출하지 않고 새로운 코드를 AI가 생성하지 않는다. 대신 이미 정의된 안전한 자동복구 플레이북은 즉시 실행한다.

- Google News 결과가 비면 검색 필터를 완화하고 broad fallback을 재시도한다.
- 네이버 공개 지수 파서가 깨지면 신형 JSON endpoint와 legacy HTML fallback을 순서대로 시도한다.
- Market runtime이 없거나 오래되면 실제 입력만 읽는 no-AI sensor 모드로 runtime을 재생성한다.
- Risk/Macro runtime이 없으면 no-AI sensor 모드로 일정·Risk 상태를 재생성하며, 실제 매크로 공급자가 없으면 unavailable로 명확히 남긴다.
- Regression Guard 상태가 없으면 6분 루프에서 다시 실행한다.
- 복구 후 Health Watchdog을 다시 실행해 해결 여부를 판정한다.

자동복구로 해결되지 않고 반복되는 문제는 recent.json에 지속 신호로 남아 1시간 ChatGPT 감독의 코드 수정 우선순위가 된다. 센서의 뉴스 제목은 발견용이며 중요한 사실 확정은 1시간 AI가 원 기사와 1차 자료를 다시 확인한다.

## 10개 단위 처리

ChatGPT 감독자는 data/supervisor/state.json의 last_processed_observation_id 뒤에 있는 관측을 시간순으로 읽는다.

미처리 관측이 10개 미만이어도 1시간 시장 리서치는 실행한다. 센서 부족은 sensor_gap으로 표시하고 현재 존재하는 관측과 웹 검색을 사용한다.

10개 이상이면 가장 오래된 10개를 하나의 배치로 처리한다.

같은 오류가 여러 번 반복되면 각각의 별도 문제로 보지 않고 하나의 지속 문제로 묶는다.

반대로 한 번만 나타났다가 사라진 신호는 일시 오류일 가능성을 고려한다.

## 사용자 피드백

GitHub Issue #1의 사용자 댓글은 기존 피드백 수집 workflow가 data/feedback/사용자_피드백.jsonl에 저장한다.

1시간 감독자는 새 사용자 피드백을 일반 자동 개선보다 우선해서 읽는다.

처리한 피드백의 마지막 comment id는 data/supervisor/state.json의 last_processed_feedback_comment_id에 기록한다.

## 감독 결과

배치 처리 결과는 data/supervisor/latest-report.json에 저장한다.

주요 필드는 batch_id, observation_ids, status, summary, actions, changed_paths, next_checks, notify다.

status는 no_change, changed, attention, failed 중 하나를 사용한다.

의미 있는 변경이나 사용자 확인이 필요한 경우 notify=true로 기록한다.

다음 6분 GitHub Actions가 이 결과를 발견하면 GitHub Issue #1과 Telegram으로 알림을 보낸다.

## 검증 방식

AI가 변경을 적용한 직후에는 validation=pending_next_observation으로 기록한다.

다음 6분 관측에서 compile, pytest, diff 검사 결과를 확인한다.

검증 실패가 지속되면 다음 10개 배치에서 우선 처리한다.

## OpenAI API Key

이 운영 방식에는 GitHub Repository Secret의 OPENAI_API_KEY가 필요하지 않다.

OPENAI_API_KEY는 사용자가 로컬 또는 별도 실행환경에서 기존 live CLI 엔진을 직접 실행하고 싶을 때만 선택적으로 사용할 수 있다.


## 6분 질문 추론 큐

6분 센서는 AI 답변을 생성하지 않지만 단순 수집기에서 끝나지 않는다. 각 관측에서 확인 가능한 변화와 불일치를 규칙 기반으로 추론해 `research_questions`를 만들고 `data/supervisor/question_queue.json`에 누적한다.

질문 생성 대상은 신규 DART 공시, 새 뉴스, 반복 키워드, 최근 6분 거래대금 상위 변화, 관련 종목 동시성, 뉴스와 수급의 시간 순서, Health/Regression 이상 등이다.

질문은 최소한 다음 성격을 포함한다.

- 사실 확인: 실제 새 정보인가, 최초/공식 출처는 무엇인가.
- 인과관계: 뉴스·공시·수급 중 무엇이 먼저 움직였는가.
- 확산: 한 종목만의 움직임인가 관련 종목으로 자금이 퍼지는가.
- 반증: 현재 설명이 틀릴 수 있는 증거는 무엇인가.
- 지속성: 다음 6분에도 같은 현상이 유지되는가.
- 시스템: 오류가 일시적인가 구조적으로 반복되는가.

같은 질문이 반복 관측되면 새 질문을 무한 복제하지 않고 `seen_count`와 연결된 `observation_ids`를 늘린다. 따라서 1시간 AI는 반복 횟수와 근거를 함께 보고 우선순위를 판단할 수 있다.

## 1시간 질문 일괄 심층연구

1시간 ChatGPT 감독은 기존 시장 리서치와 함께 `data/supervisor/question_queue.json`의 열린 질문을 읽는다.

질문을 개별적으로 기계 답변하지 말고 서로 연결해 사건의 시간 순서와 공통 원인을 조사한다. 우선순위는 높은 priority, 여러 6분 관측에서 반복된 질문, 실제 거래대금이 동반된 질문, 신규 공시·1차 자료가 있는 질문을 높게 본다.

각 배치에서 다음을 수행한다.

1. 중복되거나 같은 원인을 묻는 질문을 하나의 연구 묶음으로 합친다.
2. 웹·포털은 발견에 사용하고 중요한 사실은 1차 출처로 검증한다.
3. 질문마다 answered / partially_answered / unresolved 상태를 구분한다.
4. 답을 얻는 과정에서 생긴 새로운 질문은 후속 질문으로 다시 큐에 남긴다.
5. 미해결 질문은 다음 1시간으로 이월한다.
6. 결론에 반대되는 증거와 대체 설명을 반드시 찾는다.
7. 시장 종료 후 또는 다음 거래일에는 핵심 가설이 실제로 맞았는지 사후 확인해 연구 품질 학습 자료로 남긴다.

이 구조는 `6분 관측 → 질문 생성 → 질문 누적/강화 → 1시간 심층연구 → 답/새 가설 → 후속 질문 → 사후 검증`의 순환을 만든다.


## 질문 품질 사후학습

1시간 AI가 질문을 조사한 뒤에는 질문 자체도 평가한다. 방향성 예측 적중률만으로 좋은 질문을 정의하지 않는다.

각 처리 질문에 다음 결과를 남긴다.

- question_id / kind
- status: answered / partially_answered / unresolved
- evidence_quality: 0~1, 1차 자료와 독립 교차검증 수준
- usefulness: 0~1, 실제 시장 구조 이해·후속 조사에 기여한 정도
- 새로 생긴 후속 질문과 반증 결과

이 결과는 `data/supervisor/question_learning.json`에 누적한다. 질문 종류별 표본이 최소 10개가 되기 전에는 자동 우선순위 학습에 사용하지 않는다.

충분한 표본 뒤에도 학습 보정은 기본 priority에 최대 +1/-1만 적용한다. 따라서 과거에 유용했던 질문 유형은 조금 먼저 조사하고, 반복적으로 근거가 약했던 유형은 조금 뒤로 보내되 현재의 강한 공시·거래대금 신호를 무시하지 않는다.

목표는 질문을 많이 만드는 것이 아니라 시간이 지날수록 **실제로 답할 수 있고, 근거가 좋고, 다음 판단에 도움이 되는 질문을 먼저 만드는 것**이다.
