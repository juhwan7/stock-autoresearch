# 사용자 도움이 필요한 항목

AI가 혼자 해결할 수 없거나 사람이 명시적으로 설정해야 하는 항목을 적는다.

---

## [선택] OpenAI API Key

상태: 기본 운영에는 필요 없음

현재 기본 구조는 GitHub Actions가 6분마다 AI 없이 관측을 저장하고, ChatGPT 예약 작업이 관측 10개를 1시간 단위로 처리한다. 따라서 GitHub Repository Secret에 `OPENAI_API_KEY`를 넣지 않아도 된다.

`OPENAI_API_KEY`는 기존 `python -m autoresearch run/evolve/market-intel/risk-intel --mode live` 명령을 로컬 또는 별도 실행환경에서 직접 사용할 때만 선택적으로 필요하다.

키를 사용하는 경우에도 코드, Markdown, Issue, 채팅 로그에 직접 기록하지 않는다.

## [선택·권장] 6분 멀티소스 센서용 네이버·DART API

상태: 코드 연결 완료 / Secret이 있으면 자동 활성화

6분 센서는 키가 없어도 Google News RSS·네이버 금융 공개 페이지·Toss 상태를 계속 수집한다.

아래 Secret을 추가하면 탐색 범위가 더 넓어진다.

```
NAVER_CLIENT_ID
NAVER_CLIENT_SECRET
DART_API_KEY
```

### 네이버

네이버 Search API의 뉴스 검색과 웹문서 검색을 사용한다.

용도:
- 날짜순 최신 네이버 뉴스 탐색
- 동적 트렌드 키워드의 추가 뉴스 확인
- 기업 공식 IR·뉴스룸 후보 페이지 탐색

공식 IR 후보는 URL만으로 사실로 확정하지 않고 1시간 AI가 실제 공식 도메인인지 다시 확인한다.

### OpenDART

매 6분 현재 날짜의 최신 공시 목록을 조회하고 이전 센서 결과의 접수번호와 비교한다.

용도:
- 새 수주·계약·투자·실적·주요사항 공시를 빠르게 발견
- 뉴스가 나오기 전에 공식 공시 발생 여부 확인
- 1시간 AI 심층리서치에 공식 1차 자료 후보 전달

키가 없거나 일시 오류가 나도 다른 센서 수집은 중단하지 않는다.

## [권장] GitHub Pages 활성화

상태: 사용자 작업 필요

목적: 웹 대시보드를 GitHub Pages로 본다.

방법:

1. 저장소 `Settings`
2. `Pages`
3. Build and deployment의 Source를 `GitHub Actions`로 선택한다.

## [조건부] GitHub Actions 쓰기 권한 확인

상태: 자동 커밋이 실패할 때만 필요

확인 위치: `Settings → Actions → General → Workflow permissions`

현재 워크플로는 저장소 파일 쓰기에 필요한 최소 권한만 요청하도록 유지한다.


## [선택·fallback] 키움 REST API 읽기 전용 키 등록

상태: 선택 사항

목적: Toss Collector가 아직 연결되지 않았거나 KRX 정규장 중 일시적으로 사용할 수 없을 때 Market Tape의 fallback으로 사용한다.

현재 프로젝트는 **시세 조회만 사용하며 주문 기능은 구현하지 않는다.**

준비 방법:

1. 키움 REST API 사이트에서 사용신청을 한다.
2. 발급받은 App Key와 Secret Key를 확인한다.
3. GitHub 저장소 `Settings → Secrets and variables → Actions`로 이동한다.
4. 아래 두 Repository secret을 추가한다.

```
KIWOOM_APP_KEY
KIWOOM_SECRET_KEY
```

주의:
- 키 값 자체를 README, Issue, Markdown, 채팅 로그에 붙이지 않는다.
- 이 두 Secret이 없으면 프로젝트는 시장 분석 모듈을 실패시키지 않고 `needs_credentials` 상태로 기록한다.

현재 Provider Chain은 Toss-first이며 키움은 KRX 정규장 fallback이다.

## [권장·Toss 연결] EC2 고정 IP 6분 REST 수집

상태: 코드 구현 완료 / EC2 Runner 연결만 필요

기본 Toss 연결은 상시 WebSocket이 아니라 **6분 REST 배치**다.

매 6분 고정 IP EC2에서:

1. Toss OAuth 토큰 발급
2. 거래대금 현재 Top50 조회
3. 당일 한 번이라도 Top50에 들어온 종목 합집합 유지
4. 추적 종목 최근 1분봉 조회
5. 51위 이하로 밀린 종목도 장 마감까지 계속 추적
6. `data/providers/toss/latest.json`에 저장
7. GitHub main에 반영

Repository Secret:

```
TOSS_CLIENT_ID
TOSS_CLIENT_SECRET
```

Repository Variable:

```
TOSS_FIXED_IP_RUNNER_ENABLED=true
```

실행 workflow:

`.github/workflows/고정IP_토스시장.yml`

상세 절차:

`docs/FIXED_IP_RUNNER.md`

EC2 설치 보조 스크립트:

`scripts/ec2_toss_runner_bootstrap.sh`

### 왜 고정 IP가 필요한가

Toss Open API는 허용 IP 목록에 없는 REST/WebSocket 요청을 403으로 차단한다.

GitHub-hosted runner는 실행마다 고정된 단일 egress IP를 보장하지 않으므로 Toss 직접 호출용으로 사용하지 않는다.

### 1분 거래대금 정확도

Toss REST의 1분봉은 OHLCV를 제공하므로 개별 1분 거래대금은 기본적으로 `종가×거래량` 근사값이다.

현재 Top50 종목이 직전 6분 관측에도 Top50이었다면 Toss 거래대금 랭킹의 누적 `tradingAmount` 차분으로 해당 관측 구간 총 거래대금을 보정한다.

정확한 개별 체결 `Σ(체결가×체결량)`이 필요할 때만 기존 WebSocket Collector를 선택적으로 사용할 수 있다. 현재 프로젝트 기본 운영에는 필요하지 않다.

## [필수·Telegram 알림] Telegram Bot 연결

상태: 코드 구현 완료 / 사용자 Secret 등록 필요

목적: 1시간 감독 배치에서 실제 개선이 적용되거나 중요한 확인 사항이 생겼을 때 다음 6분 GitHub Actions를 통해 휴대폰 Telegram으로 알림을 받는다.

준비:

1. Telegram에서 `@BotFather`를 열고 `/newbot`으로 알림용 Bot을 만든다.
2. 생성된 Bot과 개인 채팅을 열고 `/start` 또는 아무 메시지나 한 번 보낸다.
3. GitHub 저장소 → `Settings → Secrets and variables → Actions`에서 먼저 `TELEGRAM_BOT_TOKEN` Repository secret을 만든다.
4. `Actions → 텔레그램 알림 테스트 → Run workflow`를 실행한다.
5. `TELEGRAM_CHAT_ID`가 아직 없으면 workflow가 Bot의 최근 메시지에서 Chat ID를 찾아 로그에 표시한다.
6. 표시된 값을 `TELEGRAM_CHAT_ID` Repository secret으로 추가한다.
7. `텔레그램 알림 테스트`를 다시 실행한다.

중요:
- Bot Token을 README, Issue, 코드, 채팅에 붙이지 않는다.
- Secret이 없거나 잘못되어도 GitHub Issue 알림은 계속 동작한다.
- 6분 관측 자체는 Telegram으로 보내지 않는다.
- no_change 감독 배치는 보내지 않는다.
- 같은 batch_id의 중복 알림을 억제한다.

연결 확인:

공식 Bot API의 `getUpdates`로 최근 Bot 메시지에서 Chat ID를 찾고, `sendMessage`로 테스트 메시지를 보낸다.

성공하면 Telegram에 `Stock AutoResearch Telegram 연결 성공` 메시지와 두 개의 버튼이 온다.

- **💬 바로 피드백** → GitHub Issue #1
- **📊 대시보드** → GitHub Pages

Telegram Bot API는 `sendMessage`와 inline keyboard를 이용한다.
