# 아이디어 보드

AI가 발견한 아이디어를 상태와 함께 누적한다.

상태는 채택, 실험중, 보류, 폐기, 재검토로 구분한다.

---

## 채택 — GitHub 웹 대시보드

아이디어: Markdown 파일만 직접 찾아다니지 않고 브라우저에서 최근 연구, 프로젝트 상태, 진화 로그, 도움 필요 항목을 한눈에 본다.

채택 이유: 사용자 가독성 개선 효과가 크고 정적 사이트로 구현하면 구조가 단순하다.

향후 개선 후보: 보고서 검색, 섹터/기업 필터, 진화 타임라인, 리서치 품질 점수 추이, 아이디어 상태 칸반.

## 채택 — 저비용 Scout + 고품질 Builder 분업

아이디어: 10분마다 고가 모델로 모든 것을 깊게 처리하지 않고 Scout가 먼저 가치 여부를 판단한다.

채택 이유: 하루 144회의 Tick을 현실적인 비용으로 유지하기 위해서다.

## 보류 — OpenDART/KRX 직접 API 수집

아이디어: 웹 검색에만 의존하지 않고 공시·시장 데이터를 API로 구조화해 직접 수집한다.

보류 이유: OpenDART API 키 등 사용자 설정이 필요하고 KRX 데이터 접근 방식도 별도 설계가 필요하다.

진행 조건: 필요한 키/접근 방법이 준비되면 우선순위 높은 후보로 재검토한다.

## 보류 — AI가 Workflow 자체까지 자동 수정

아이디어: Evolution Agent가 `.github/workflows`도 자유롭게 수정한다.

보류 이유: 잘못된 한 번의 수정으로 10분 루프 자체가 멈추거나 권한이 과도하게 확대될 수 있다.

대안: AI는 변경안을 IDEA/HELP_NEEDED로 작성하고 사람이 승인하면 적용한다.


## 채택 — 국내시장 Market Tape

아이디어: 10분마다 거래대금 상위 종목과 1분봉을 읽어 현재 장세를 정량화한다.

핵심 지표: 분당 거래대금, 거래대금 burst 배수, 장후반 거래대금 비중, 시장 폭, 상위 종목 집중도, 신규주 흐름, 그룹/섹터 동조.

## 실험중 — 종가베팅 이벤트 사후평가

아이디어: 장후반 조건을 만족한 전체 표본을 저장한 뒤 다음 거래일 갭·MFE·MAE를 자동 채워 조건별 실패 패턴을 찾는다.

현재 상태: 이벤트 스키마와 통계 엔진을 먼저 구축했다. 실제 데이터 연결 후 자동 이벤트 생성/완결 로직을 확장한다.

## 실험중 — 단기스윙 눌림 통계

아이디어: 이전 대량 거래 상승 파동 이후 눌림폭, 거래대금 감소, 5·20일선 위치, 첫 재가속을 이벤트로 만들어 1·3·5일 성과를 추적한다.

현재 상태: 통계 스키마 구축. 일봉 과거데이터 백필과 이벤트 탐지기가 다음 단계다.

## 재검토 — OpenDART/KRX 직접 API 수집

기존에는 보류했지만 국내시장 정량 분석 요구가 구체화되어 다시 우선순위가 높아졌다. 다만 분봉은 키움 REST가 현재 목적에 더 직접적으로 맞으므로, 우선 키움 시세를 붙이고 공시/상장 메타데이터는 OpenDART/KRX로 보강하는 순서를 채택한다.


## 채택 — 전체시장 breadth와 주도주 Tape 분리

아이디어: KOSPI/KOSDAQ 전체 상승·하락 종목 수와 거래대금 상위 종목의 1분봉을 별도 계층으로 본다.

채택 이유: 상위 거래대금 종목만으로 전체 장세를 일반화하는 오류를 줄일 수 있고, 지수와 시장 폭·주도주 집중도가 엇갈리는 장세도 포착할 수 있다.

구현: 키움 `ka20001` + `ka10032` + `ka10080`.

## 채택 — 시간 동기화된 그룹 수급

아이디어: 같은 그룹 여러 종목이 같은 날 올랐다는 이유만으로 동조수급으로 보지 않고, 3분 범위 안에서 상승과 거래대금 burst가 동시에 발생한 종목 수를 계산한다.

채택 이유: 사용자가 원하는 “여러 종목에 동시에 돈이 들어오는 장면”에 더 가깝다.

## 보류 — 분봉 실제 체결대금 정밀 집계

아이디어: 1분봉 종가×거래량 근사 대신 개별 체결가격×체결량을 합산해 실제 1분 거래대금을 만든다.

보류 이유: GitHub Actions는 10분마다 시작하고 종료되는 단기 실행 환경이라 장중 WebSocket 체결 스트림을 지속적으로 보존하기에 적합하지 않다. 틱 조회만으로 매번 전 종목 체결을 재구성하면 API 호출량도 크게 늘 수 있다.

현재 대안: 분봉 종가×분봉 거래량을 사용하고 `amount_estimated=true`를 명시한다.

진행 조건: 상시 실행 가능한 별도 수집기 또는 정확한 분 단위 거래대금 공급원을 확보하면 교체한다.

## 재검토 — 과거 데이터 백필

아이디어: 오늘부터 표본을 쌓기만 하면 통계가 느리게 늘어나므로 과거 일봉·분봉을 가능한 범위까지 한 번에 수집해 종가베팅/눌림 연구 표본을 초기화한다.

장점: 조건별 MFE/MAE 통계를 훨씬 빨리 볼 수 있다.

주의: 데이터 제공 기간·API 호출량·과거 분봉 보존 범위를 먼저 확인해야 한다. 과거 시점 당시의 거래대금 상위 Universe를 사후 데이터로 정확히 복원할 수 있는지도 검증해야 한다.

## 선행과제 — 통계 조건 버전 관리

아이디어: AI가 앞으로 눌림 조건을 개선할 때 기존 표본과 새 표본이 섞이면 비교가 깨질 수 있다.

도입 전제: 각 이벤트에 `cohort_version`을 기록하고, 조건을 변경하면 v1/v2처럼 분리해 성능을 비교한다.

이 기능을 넣기 전에는 Evolution Agent가 `config/market_intel.yaml`의 연구 코호트 임계값을 자동 변경하지 않게 유지한다.

## 후보 — 기업집단 자동 매핑

아이디어: 현재 한화처럼 검증된 그룹을 수동 메타데이터로 보강하지만, 향후 공정거래위원회 기업집단 자료 등 1차 자료를 이용해 한화·두산·LS·현대차 등 그룹 관계를 자동 갱신한다.

이유: 이름이 비슷하다는 이유만으로 그룹주로 묶는 오류를 피하면서 대형 그룹 동조 장세를 넓게 포착하기 위해서다.
