# 연구 무결성 로드맵

이 문서는 외부 프레임워크로 프로젝트를 교체하지 않고, 현재 Stock AutoResearch 구조 위에 연구 신뢰성과 장기 기억을 점진적으로 강화하기 위한 계획이다.

## 현재 이미 있는 기반

- Researcher → Critic → Chief의 검증 루프
- claim별 status / confidence / source_ids
- 1차 자료 우선과 반론 탐색 규칙
- research quality score
- Health Watchdog의 stale data 감시
- Evolution Tick / change manifest / 결정 원장
- Regression Guard의 7일·30일 품질 기준선
- data/state의 연구 상태와 reports의 사람이 읽는 결과
- Market/Risk의 semantic dirty-state

따라서 같은 기능을 다른 이름으로 다시 만들지 않는다.

## 1차 — 무결성 기반

### Claim Ledger V1

Researcher가 이미 생성하는 claims와 sources를 그대로 append-only JSONL에 보존한다.

경로:

`data/research/claims/YYYY-MM-DD.jsonl`

각 행은 claim_id, run_id, 관측시각, 상태, 신뢰도, source_ids, 출처 snapshot, 누락 source_id, Critic 판정을 가진다.

기존 보고서와 research_state 형식은 유지한다.

### 정적 경로 무결성

한글 파일명 변경처럼 파일은 존재하지만 설정이 옛 경로를 가리키는 문제를 CI에서 잡는다.

특히 Risk dirty-state logic_files와 Evolution protected_paths는 실제 파일 존재 여부를 검증한다.

## 2차 — Research CI / Contradiction / Trace

- 대표 연구 사례를 작은 versioned eval dataset으로 만든다.
- claim의 source_ids가 실제 출처를 가리키는지 deterministic evaluator로 검사한다.
- 같은 entity/metric/period에 상충하는 claim을 후보로 표시한다.
- LLM 단계별 trace에는 run_id, stage, model, 시작/종료, 성공/실패, input/output hash를 기록한다.
- 원문 프롬프트 전체나 Secret은 trace에 저장하지 않는다.

기존 Critic은 한 번의 연구 안에서 반론을 찾고, Contradiction Hunter는 여러 날짜·여러 run 사이의 충돌을 찾는 역할로 분리한다.

## 장기 — Project Memory / Knowledge Graph / Issue Queue

Claim Ledger와 누적 결과가 충분해지면 topic/company/industry/source/claim 사이의 관계를 파생 그래프로 만든다.

그래프가 원본이 되는 것이 아니라 append-only Claim Ledger와 기존 run/report가 원본이며, Knowledge Graph는 재생성 가능한 index로 취급한다.

GitHub Issue는 모든 10분 Tick마다 만들지 않는다. 자동수정이 금지된 high-risk 제안이나 사용자 작업이 필요한 항목 중 중복 fingerprint가 없는 것만 Issue 후보로 승격하는 방식이 적합하다.

Prediction Ledger는 매수·매도 추천 시스템으로 만들지 않는다. 연구 문서 안에서 명시적으로 검증 가능한 가설, 예상 확인시점, 실제 결과를 기록하는 연구용 ledger로 한정한다.

## 도입하지 않는 것

현재 단계에서는 LangGraph, Langfuse, n8n, OpenBB 전체 프레임워크를 의존성으로 추가하지 않는다.

필요한 설계 개념만 현재 Python/YAML/JSONL 구조에 맞게 구현하고, 기존 자동화와 데이터 포맷을 우선 보존한다.
