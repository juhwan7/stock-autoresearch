# UI·UX 자기진화 규칙

## 목적

Stock AutoResearch의 GitHub Pages는 데이터가 가장 많은 화면이 아니라 사용자가 몇 초 안에 현재 시장의 큰 틀과 중요한 변화를 파악할 수 있는 화면을 목표로 한다.

핵심 흐름은 다음과 같다.

**큰 시장 흐름 파악 → 중요한 변화 확인 → 관심 항목만 펼쳐 깊게 확인**

## 정보 계층

모든 화면은 가능하면 다음 질문 순서로 구성한다.

1. 지금 무슨 상황인가
2. 무엇이 가장 중요한가
3. 무엇이 변했는가
4. 앞으로 무엇을 확인해야 하는가
5. 상세 근거와 원자료는 무엇인가

PRIMARY는 현재 핵심 위험·동인·가까운 일정·새 이슈처럼 먼저 보여야 하는 정보다.

SECONDARY는 외국인 수급·상대강도·거래대금·금리·환율·기존 ACTIVE 이슈처럼 판단을 보조하는 정보다.

DETAIL은 계산 방식·출처·history·전체 기사·시스템 로그·Regression·Health 세부처럼 필요할 때 확인하는 정보다.

DETAIL은 가능한 경우 semantic HTML의 details/summary를 먼저 사용한다.

## Progressive Disclosure

기본 원칙은 **핵심 먼저 → 클릭 → 상세 펼침**이다.

기본 접힘 후보:
- 긴 리서치와 근거
- 이전 이슈 history
- 전체 출처
- 계산 방식
- 상세 통계
- 오래된 일정
- 낮은 중요도 항목
- 공급자 상세
- Regression/Health 상세
- 진단 로그
- AI 변경 원문
- 과거 관측

단, 현재 HIGH/CRITICAL 위험이나 시장의 핵심 상태는 기본 접힘 뒤에 숨기지 않는다.

접힌 상태에서도 최소한 무엇인지, 언제인지, 왜 중요한지는 알 수 있어야 한다.

한 accordion을 열면 다른 것을 강제로 닫는 구조는 기본값으로 사용하지 않는다. 비교가 필요하면 여러 항목을 동시에 펼칠 수 있어야 한다.

## 카드와 페이지 역할

한 카드에는 가능하면 하나의 질문만 답하게 한다.

예:
- 현재 시장은 어떤 상태인가
- 지금 가장 중요한 이슈는 무엇인가
- 다음 위험 일정은 언제인가
- 돈은 어디로 움직이는가
- 지수보다 강한 것은 무엇인가

페이지 역할:
- 요약: 큰 흐름과 가장 중요한 것
- 국내시장: 국내 지수·수급·거래대금·섹터
- 거대자금: 예탁금·신용·펀드 등 큰 자금
- 글로벌·리스크: 해외시장·금리·환율·원유·예정 이벤트
- 이슈 추적: 사건 생명주기
- 리서치: 심층 분석
- 상대강도: 지수 대비 강약
- 시스템: 공급자·Health·Regression·AI 운영

메인 화면은 원자료 저장소가 아니다. 상세는 전문 페이지로 보낸다.

## 시각적 원칙

화이트 테마를 기본으로 유지한다.

- 흰색/매우 연한 회색 배경
- 얇은 경계
- 과도한 그림자·gradient 금지
- 충분한 여백과 텍스트 대비
- 상태 badge는 작고 명확하게
- 색상은 정보 의미에만 사용
- 빨강/초록 도배 금지
- CRITICAL/HIGH/NEW/ESCALATING 등 실제 의미 변화만 강조

변화 없는 정보는 조용하게 표현하고 새 변화·강화·완화가 더 잘 보이게 한다.

숫자만 던지지 말고 사람이 해석한 의미를 함께 보여준다.

예:
- Foreign -2458 → 외국인 순매도 확대 · -2,458억
- 461.1시간 후 → D-19 · 19일 5시간 남음

## 화면 밀도

중요도 낮은 카드 때문에 중요한 정보가 아래로 밀려나면 안 된다.

목록은 기본 상위 3~5개처럼 제한하고 전체 보기·상세 페이지·접힘으로 확장하는 방식을 우선 검토한다.

단, 전문 페이지 자체가 전체 원장을 보는 목적이면 필터와 details를 사용해 전체 데이터를 유지할 수 있다.

## 모바일

모바일을 데스크톱 축소판으로 만들지 않는다.

반드시 검토:
- 카드 폭
- 제목 줄바꿈
- tap 영역
- 표 가로 스크롤
- 그래프
- navigation
- details summary
- sticky 요소
- 첫 화면의 핵심 정보

보조정보는 모바일에서 접거나 아래로 이동할 수 있다.

## 상태 기억

정적 details 섹션은 복잡도를 늘리지 않는 범위에서 localStorage 등으로 사용자의 펼침/접힘 상태를 유지할 수 있다.

저장 실패나 브라우저 제한이 있어도 기본 HTML details 동작이 깨지면 안 된다.

## A(:00)의 UI 역할

A는 매 실행에서 ui_ux를 기본 검토축 중 하나로 포함한다.

질문:
- 첫 화면에서 가장 먼저 보이는 것이 정말 가장 중요한가
- 사용자가 계산해야 이해되는 숫자가 있는가
- 카드가 너무 많은가
- 접어서 정리할 내용이 있는가
- 다른 전문 페이지로 옮겨야 할 정보가 있는가
- 새로운 변화가 충분히 눈에 띄는가
- 모바일에서 읽기 쉬운가
- 빈 카드가 공간을 낭비하는가
- 같은 정보가 여러 페이지에 중복되는가

실제 문제가 있고 안전한 변경이면 구현·테스트한다.

## B(:30)의 UI 역할

B는 A의 UI를 그대로 유지하지 않는다.

검토:
- 정보 과다
- 중복 카드
- 지나친 강조
- 색상 남용
- 세로 공간 낭비
- 모바일 깨짐
- 빈 데이터
- 긴 설명
- 클릭하기 어려운 요소
- 핵심이 아래로 밀림
- 상세가 기본 화면을 방해함

필요하면 접기, 통합, 순서 변경, 제거, 전문 페이지 이동, 축약, 강조 감소를 실행한다.

B의 핵심 질문은 **이 기능을 계속 기본 화면에 보여줄 필요가 있는가?** 이다.

## 데이터 → 분석 → 사용자 화면

A/B가 새로운 데이터나 기능을 추가할 때 반드시 다음을 판단한다.

1. 이 데이터가 사용자가 직접 봐야 하는가
2. YES라면 어느 페이지가 책임져야 하는가
3. 메인에는 요약만 필요한가
4. 상세는 details 또는 전문 페이지로 내려야 하는가
5. NO라면 내부 분석용으로만 둘 것인가

backend 데이터라고 모두 화면에 노출하지 않는다.

## UI 실험 생명주기

UI도 idea → experiment → active → review → simplify/remove를 따른다.

새 UI가 실제로 중요한 정보를 더 빨리 찾게 하는지 검증한다. 복잡성만 늘리면 단순화하거나 제거한다.

## 검증

UI 변경 후 가능한 범위에서:
- Desktop 구조
- Mobile breakpoint
- 긴 제목
- 빈 데이터
- 많은 데이터
- 펼침/접힘
- 내부 링크
- JavaScript syntax
- semantic details/summary
- fallback

을 확인하고 자동 테스트를 추가한다.

## 장기 기억과 Telegram

중요한 UI 결정은 memory/project/design/에 남겨 다른 AI가 몇 달 뒤 같은 복잡성을 다시 만들지 않게 한다.

실제 UI 변경이 있으면 Telegram에 무엇을 접었고, 무엇을 앞에 배치했고, 왜 좋아졌는지 짧게 보고한다. 변경이 없으면 억지로 UI 보고를 만들지 않는다.


## 사용자 화면 한국어·구조화 표시 규칙

- 사용자-facing Pages에서는 내부 JSON 객체, 배열, `[object Object]`, Python/JavaScript 객체 표현을 그대로 출력하지 않는다.
- 원본 JSON 필드명과 enum은 데이터 계층에 유지하고, 화면에서는 공통 formatter를 통해 자연스러운 한국어 문장·목록·카드로 변환한다.
- `NEW/ACTIVE/WATCHING/ESCALATING/EASING/RESOLVED`, `HIGH/MEDIUM/LOW`, `verification_pending/investigating/no_change/stale` 같은 내부 상태값은 화면에서 한국어로 표시한다.
- 객체 구조가 예상과 달라도 `JSON.stringify`로 사용자 화면에 노출하지 않는다. 읽을 수 있는 필드를 선택하고, 불가능하면 `세부 내용을 구조화해 표시할 수 없습니다.`처럼 안전한 한국어 fallback을 사용한다.
- `issue_id`, 내부 오류 코드, change_id 같은 개발자용 식별자는 기본 화면 제목·요약으로 사용하지 않는다. 꼭 필요하면 `개발자용 원본 정보` 접힘 영역에 둔다.
- 페이지 eyebrow/kicker와 일반 소제목은 고유명사·표준 약어(AI, KOSPI, KOSDAQ, Nasdaq, S&P 500, DART, CPI, FOMC, USTR, NXT 등)를 제외하고 한국어를 기본으로 한다.
- 새 상세보기 렌더러를 추가할 때는 실제 Supervisor/issue/risk/operations 데이터의 중첩 객체를 테스트해 원시 JSON과 영문 enum이 다시 노출되지 않는지 회귀검증한다.


## AI 협업 회의 화면

`AI 대화` 화면은 내부 로그를 그대로 나열하는 페이지가 아니라 A/B의 자율 개선 과정을 사람이 빠르게 이해하는 페이지다.

기본 정보 계층은 다음 순서를 유지한다.

1. 현재 공동 작업 한 문장
2. 활성 incident
3. 최근 해결 incident
4. 이번 실제 변경 여부
5. 다음 검증
6. A↔B 실행 타임라인
7. 상세 근거와 원본 Supervisor JSON

같은 장애의 하위 증상은 여러 카드로 늘리지 않는다. 카드 기본 상태에서는 제목·상태·짧은 요약·다음 확인만 보여주고, 근거·history·개발자용 파일 경로는 펼침 안으로 내린다.

`changed_paths`가 Supervisor 결과 JSON 하나뿐인 경우에는 “운영 결과 기록만 갱신”으로 표시하고 코드/UI를 바꾼 것처럼 보이지 않게 한다. resolved 항목은 현재 장애보다 시각적 우선순위를 낮추며, 오래된 history가 첫 화면을 밀어내지 않게 한다.
