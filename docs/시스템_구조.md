## 데이터 흐름

### 시장 데이터

```text
고정 IP Toss Collector
→ 실제 체결 snapshot
→ TossCollectorBridge
→ MarketIntelEngine
→ data/market/latest.json
→ 종가베팅·눌림 이벤트 CSV
→ Risk / 대시보드
```

신선한 Toss 데이터가 없을 때 KRX 정규장에서는 키움 REST가 fallback으로 동작한다. NXT 값을 추측해서 채우지 않는다.

### 시장 리서치

```text
멀티소스 Market Scout
├─ 네이버 뉴스 / 네이버 금융
├─ 국내 경제·통신사
├─ Reuters 등 글로벌 뉴스
├─ Google News / 일반 웹
├─ DART / KRX / 정부 / 기업 IR
└─ SEC / Fed 등 해외 1차 자료
→ 후보 점수화
→ Researcher
→ Fact Verifier
→ Skeptic / Critic
→ 필요하면 반복 추가 조사
→ Chief Researcher
→ reports/
→ data/runs/
→ data/state/research_state.json
→ data/research/claims/YYYY-MM-DD.jsonl
```

Claim Ledger는 새로운 판단 엔진이 아니라 Researcher가 이미 생성한 `claims + source_ids`를 장기 비교 가능한 형태로 보존하는 계층이다.

### Overnight Risk

```text
공식 일정 + 매크로 + Market Tape
→ semantic hash
→ 의미 변화 여부
→ 필요할 때만 Risk Evaluator
→ data/risk/
→ 종가베팅 이벤트에 밤사이 최대 Risk 반영
```

## 기억 계층

현재 기억은 두 종류로 나눈다.

### 실행·단기 상태

- `data/runs/`: 한 번의 연구 실행 전체 JSON.
- `data/state/`: 최신 연구 주제 상태.
- `data/market/*state*.json`: Market Tape 의미 상태.
- `data/risk/state.json`: Risk 의미 상태.
- `data/health/`: 운영 상태.
- `data/regression/history/`: 품질 스냅샷.

### 장기·사람/연구 기억

- `data/research/claims/`: 출처 연결이 포함된 append-only Claim Ledger.
- `data/supervisor/queue/`: 10분 슬롯 기반 비AI 센서 관측.
- `data/evolution/changes/`: 변경 전후 내용과 Hash가 있는 change manifest.
- `docs/결정_원장.md`: 중요한 설계 결정.
- `docs/아이디어_보드.md`: 채택·보류·폐기 아이디어.
- `docs/실험_기록.md`: 실험·회귀 결과.
- `reports/`: 사람이 읽는 최종 연구 결과.

현재 main에 모든 런타임 이력이 이미 누적되어 있다는 뜻은 아니다. 위 경로는 실행 시 생성되는 구조이며, raw Toss snapshot처럼 Git에 보존하지 않는 데이터도 있다.

## 자동화

- `.github/workflows/연속연구와진화.yml`: 10분 비AI 센서 관측 큐.
- `.github/workflows/10분센서_보조복구.yml`: 매 10분 슬롯 시작 5분 뒤 canonical 저장 여부를 확인하고, 누락이며 활성 센서가 없을 때만 같은 슬롯을 고정해 재실행하는 경량 heartbeat.
- `.github/workflows/고정IP_토스시장.yml`: self-hosted 고정 IP 시장 데이터.
- `.github/workflows/테스트.yml`: compile, pytest, dry-run, Health, Regression, 대시보드 검증.
- `.github/workflows/페이지배포.yml`: site 변경 시 Pages 즉시 배포.

main writer는 무조건 하나의 장시간 concurrency queue로 묶지 않는다. 10분 센서 지연을 막기 위해 쓰기 영역을 분리하며, Recovery는 운영 상태판 파일을, 센서는 시장·관측 canonical 데이터를 우선 소유한다. 예상 밖 핵심 파일 충돌은 성공으로 숨기지 않고 실패로 표면화한다.

## 변경 권한

Evolution Agent의 자동 수정 범위와 보호 범위는 `config/자기진화.yaml`과 [자기진화 규칙](자기진화_규칙.md)이 함께 정의한다.

고위험 영역은 자동수정하지 않고 제안으로 남긴다. 새 기능을 추가하더라도 기존 state/report/시장 통계 포맷의 호환성을 우선한다.

## 알림·사용자 피드백 루프

```text
:00/:30 A/B Supervisor 심층 리서치·감독
→ 실제 개선 / 중요 시장 변화 / Health 경고 / Regression 이벤트
→ GitHub Issue #1 댓글
├→ GitHub 모바일 알림
└→ Telegram Bot API 알림
    ├→ 바로 피드백 버튼 → Issue #1
    └→ 대시보드 버튼 → GitHub Pages
→ 사용자 답글
→ issue_comment workflow 즉시 실행
→ docs/사용자_피드백.md + data/feedback/사용자_피드백.jsonl
→ 다음 Evolution Scout가 최우선으로 읽음
```

변경이 없으면 알림을 만들지 않는다. 동일한 Health/Regression 상태는 안정적인 fingerprint로 중복 알림을 억제한다.

사용자가 change_id를 쓰지 않고 `좋아`, `보류`처럼 짧게 답해도 직전 AI 알림과 자동 연결한다.

사용자 피드백은 일반 아이디어보다 우선하지만 보호파일·테스트·기능 단위 롤백 안전규칙을 우회하지 않는다.


Telegram은 별도 판단 엔진이 아니라 GitHub Issue 알림과 동일한 의미 이벤트를 전달하는 추가 채널이다. `TELEGRAM_BOT_TOKEN`과 `TELEGRAM_CHAT_ID`은 GitHub Actions Secret으로만 읽으며 저장소 파일에는 저장하지 않는다.
