# 자동 회귀 탐지와 기능 단위 롤백

목표는 AI가 새 아이디어를 적용한 뒤 기존 품질을 망가뜨리는 것을 자동으로 찾는 것이다.

## 전체 저장소 롤백을 하지 않는다

Regression Guard는 git reset으로 저장소 전체를 과거 시점으로 되돌리지 않는다.

Evolution Agent가 자동 변경을 적용할 때마다 변경 manifest에 다음을 보존한다.

- change_id
- 변경 시각
- 변경한 파일
- 각 파일의 변경 전 내용과 Hash
- 변경 후 내용과 Hash
- 도입 이유
- 기대효과
- 위험도

회귀가 확인되면 해당 manifest의 파일만 변경 전 내용으로 복원한다.

예를 들어 변경 100개 중 37번째 기능만 문제라면 37번째 변경만 복원하고, 서로 독립적인 38~100번째 변경은 유지한다.

## 이후 변경을 덮어쓰지 않는다

문제 변경 이후에 같은 파일이 다시 수정됐다면 자동 롤백하지 않는다.

또 현재 파일 Hash가 문제 기능 도입 직후 Hash와 다르면 자동 복원을 막는다.

이 경우 상태를 quarantined로 바꾸고 사람 또는 상위 AI 검토 대상으로 남긴다.

즉 “롤백 때문에 나중 작업이 사라지는 것”을 방지한다.

## 품질 기준

매 10분 품질 스냅샷을 누적한다.

현재 V1 품질 구성:
- 리서치 quality_score
- Health Watchdog 상태
- 시장·매크로·Risk 데이터 완성도

변경 후 품질을 변경 전 7일·30일 기준선과 비교한다.

자동 롤백은 보수적으로 수행한다.

기본 조건:
- 7일 기준 대비 의미 있는 악화
- 30일 기준 대비 의미 있는 악화
- 리서치 품질도 함께 악화
- 충분한 표본
- 이후 같은 파일을 건드린 변경이 없음
- 현재 파일이 해당 기능 도입 직후 상태와 같음

하나라도 확실하지 않으면 삭제하지 않고 quarantine을 우선한다.

## 즉시 실패와 장기 회귀는 다르다

코드가 테스트를 바로 깨뜨리면 Evolution Agent가 같은 Tick에서 즉시 원복한다.

Regression Guard는 테스트는 통과했지만 며칠 뒤 품질을 악화시킨 변경을 찾는다.
