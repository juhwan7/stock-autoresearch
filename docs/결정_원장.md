# 결정 원장

프로젝트의 중요한 설계 결정을 시간순으로 기록한다.

## 2026-09-25 — 10분 Continuous Loop 도입

상태: 도입

발견: 하루 한 번 실행으로는 “AI가 계속 생각하면서 프로젝트를 진화시키는” 목적을 충족하기 어렵다.

결정: 10분마다 시장 조사와 프로젝트 개선 사고를 수행하는 Continuous Loop 구조로 전환한다.

이유: 변화 감지와 개선 사이의 지연을 줄이고, 시장 리서치와 프로젝트 자체의 발전을 하나의 지속 루프로 만들기 위해서다.

기대효과: 새로운 시장 변화와 프로젝트 개선 아이디어를 더 빠르게 발견할 수 있다.

위험: API 호출 비용 증가, 의미 없는 반복, GitHub Actions 지연 및 동시 쓰기 충돌 가능성이 있다.

대응: 저비용 Scout 모델, 의미 있는 변화 Gate, 단일 writer concurrency, 변경 수 제한을 사용한다.

## 2026-09-25 — 무제한 자기수정 대신 위험 기반 자동수정

상태: 도입

발견: AI가 워크플로·권한·비밀키·자기 안전장치까지 자동으로 바꾸면 작은 오류가 프로젝트 전체를 망가뜨릴 수 있다.

결정: 낮은/중간 위험 변경은 자동 적용하고, 높은 위험 변경은 제안으로만 기록한다.

이유: 자율성과 장기 안정성을 동시에 확보하기 위해서다.


## 2026-09-25 — 국내시장 분봉 거래대금 중심 Market Tape 도입

상태: 도입

발견: 뉴스 기반 시장 리서치만으로는 사용자가 중요하게 보는 종가베팅·눌림·동조수급을 객관적으로 판단하기 어렵다.

결정: 국내시장은 별도의 Market Tape 계층을 두고 거래대금 상위 Universe와 1분봉을 분석한다.

이유: 같은 상승이라도 거래대금이 부족하면 신뢰도가 낮을 수 있으며, 여러 관련 종목에 같은 시간대 자금이 들어오는 흐름은 개별 뉴스와 다른 시장 정보를 준다.

기대효과: “무슨 장세인지”를 기사 제목이 아니라 실제 돈의 흐름으로 설명할 수 있다.

위험: 분봉 데이터 호출량, 데이터 누락, 분 거래대금 근사 오차가 있다.

대응: 상위 Universe만 상세 조회하고, 데이터 품질과 근사 여부를 결과에 남긴다.

## 2026-09-25 — 종가베팅/눌림 통계는 전체 표본을 누적

상태: 도입

발견: 상승에 성공한 차트만 사후적으로 보면 실제 승률과 위험을 과대평가할 수 있다.

결정: 조건을 충족한 전체 이벤트를 저장하고 다음 날/1·3·5일 MFE·MAE를 사후평가한다.

이유: “평균적으로 몇 % 빠지고 반등하는가” 같은 질문에 생존자 편향 없이 답하기 위해서다.

검증 기준: 최소 표본 수 이전에는 통계 결론을 내리지 않고 표본 축적 중으로 표시한다.


## 2026-09-25 — 전체시장 폭과 주도주 Market Tape를 분리

상태: 도입

발견: 거래대금 상위 일부 종목만 보고 전체 시장이 강하거나 약하다고 일반화하면 왜곡될 수 있다.

결정: KOSPI·KOSDAQ 전체 상승/보합/하락 종목 수와 지수 흐름은 별도 전체시장 계층으로 읽고, 거래대금 상위 종목의 1분봉은 주도 자금의 위치와 속도를 읽는 상세 Market Tape로 분리한다.

이유: “지수는 강한데 실제 상승 종목은 적은 장”, “지수는 보합인데 신규주·특정 그룹으로 자금이 집중되는 장”처럼 서로 다른 장세를 구분하기 위해서다.

## 2026-09-25 — 분봉 거래대금은 절대값과 상대값을 동시에 연구

상태: 도입

결정: 각 종목에 대해 평소 분봉 거래대금 대비 burst뿐 아니라 5억·10억·20억·50억원 이상 1분봉의 횟수와 최대 1분 거래대금을 함께 저장한다.

이유: 같은 3배 burst라도 평소 유동성이 매우 작은 종목과 실제 수십억원이 체결되는 종목의 의미가 다르기 때문이다.

추가 결정: 신규상장주 집단에서는 10억·20억원 이상 분봉이 총 몇 회, 몇 종목에서 발생했는지도 집계한다.

## 2026-09-25 — 동조 수급은 시간 동기화를 요구

상태: 도입

결정: 같은 그룹·섹터 종목이 단순히 같은 날 상승한 것만으로 동조 수급으로 분류하지 않는다. 기본값으로 3분 범위 안에서 여러 종목의 가격 상승과 거래대금 burst가 함께 발생해야 강한 동조로 기록한다.

이유: 사용자가 관찰하려는 것은 이름이 비슷한 종목의 동반 상승이 아니라 같은 시간대에 실제 자금이 여러 종목으로 들어오는 장면이기 때문이다.

## 2026-09-25 — 종가베팅 연구 Universe 확대와 결과 확률화

상태: 도입

결정: 장중 상세 분석은 비용을 고려해 상위 일부 종목을 깊게 보되, 장 마감 종가베팅 연구는 거래대금 상위 50개를 기본 Universe로 확대한다.

결정: 중앙 MFE/MAE뿐 아니라 다음 날 +3/+5% MFE 도달 비율, -3/-5% MAE 역행 비율, 갭상승 비율을 함께 계산한다.

이유: 평균값 하나보다 실제 분포와 실패 빈도를 보는 것이 종가베팅의 위험을 이해하는 데 더 적합하다.

## 2026-09-25 — 눌림 반등의 이전 하락폭을 역으로 측정

상태: 도입

결정: 눌림 표본의 1·3·5거래일 MFE/MAE를 누적하고, 5거래일 안에 +5% 또는 +10% MFE가 발생한 표본만 다시 모아 그 전에 실제로 얼마나 눌렸는지 중앙값과 분위수를 계산한다.

이유: “평균적으로 어느 정도 하락한 뒤 반등이 나오는가”를 성공 차트 몇 개의 인상으로 판단하지 않고 전체 코호트에서 역으로 측정하기 위해서다.

## 2026-09-25 — 장세 조건을 종가베팅 이벤트와 함께 보존

상태: 도입

결정: 각 종가베팅 연구 이벤트에 KOSPI/KOSDAQ 등락률·상승종목 비율, 거래대금 Top10 집중도, 신규주 burst 강도, 동시 그룹수급 여부를 함께 저장한다.

이유: 앞으로 같은 차트 패턴이라도 “넓은 상승장”, “소수 종목 집중장”, “신규주 장세”, “그룹주 장세”에서 결과가 어떻게 달라지는지 조건부 통계를 만들기 위해서다.

## 2026-09-25 — 마지막 유효 장세와 실행 상태 분리

상태: 도입

결정: 장외 시간 실행이나 일시적인 데이터 부재가 마지막 유효 장세를 덮어쓰지 않도록 `latest.json`, `runtime.json`, `dry_run_latest.json`을 분리한다.

이유: 장이 끝난 뒤 웹 대시보드가 “데이터 없음”으로 바뀌어 당일 장세 기록을 잃는 문제와 dry-run 합성 데이터가 실전 상태를 오염시키는 문제를 동시에 막기 위해서다.


## 2026-09-25 — 단일 대형 리스크가 점수합을 이길 수 있는 Risk Veto

상태: 도입

발견: 종목·섹터·시장 조건이 좋아도 CPI·FOMC·고용처럼 밤사이 광범위한 가격 재평가를 일으킬 수 있는 이벤트 하나가 다음날 갭을 크게 바꿀 수 있다.

결정: 리스크를 단순 합산점수 하나로 만들지 않고, 누적 리스크와 별도로 가장 큰 단일 리스크를 보존한다. severity 5 이벤트가 임박한 경우 HIGH 또는 VETO로 승격할 수 있다.

이유: 작은 위험 여러 개보다 큰 이벤트 하나가 종가베팅 손익분포를 더 크게 바꿀 수 있기 때문이다.

## 2026-09-25 — 10분 Heartbeat + 의미 상태 변경 시 AI 재호출

상태: 도입

발견: 10분마다 동일한 시장·일정·매크로 입력으로 전체 AI 판단을 반복하면 비용과 중복이 커진다.

결정: 10분마다 데이터는 확인하지만 일정 위험단계, 반올림된 매크로 구간, 국내장 장세, Risk 규칙 문서 Hash가 바뀔 때만 Risk Evaluator를 다시 호출한다.

이유: market-memo의 상태 감시처럼 “변화가 있을 때 판단”하는 구조가 더 안정적이고 설명 가능하기 때문이다.

안전장치: 의미 상태가 장시간 변하지 않아도 설정된 주기마다 강제 재평가한다.

## 2026-09-25 — 종가베팅 표본에 밤사이 최대 Risk를 저장

상태: 도입

결정: 종가베팅 연구 표본에 최신 Risk뿐 아니라 KRX 종가 이후 관측된 최대 Overnight Risk Level을 저장한다.

이유: 이후 VETO였던 날과 LOW/WATCH였던 날의 다음날 갭·MFE·MAE 차이를 실제 통계로 비교하기 위해서다.


## 2026-09-25 — 회귀 롤백은 저장소 전체가 아니라 기능 변경 단위로 수행

상태: 도입

발견: AI가 많은 개선을 누적한 뒤 특정 기능 하나가 품질을 악화시켰을 때 저장소 전체를 과거 시점으로 되돌리면 이후의 독립적인 개선까지 사라질 수 있다.

결정: Evolution Agent가 자동 변경을 적용할 때 change_id별 manifest를 생성하고, 변경 전/후 파일 내용과 Hash를 보존한다. 회귀가 확인되면 해당 change_id가 수정한 파일만 복원한다.

안전장치: 해당 기능 이후 같은 파일이 다시 수정됐거나 현재 파일 Hash가 도입 직후와 다르면 자동 복원을 차단하고 quarantined 상태로 격리한다.

이유: 예를 들어 100개 작업 중 37번째 기능만 문제여도 38~100번째의 독립적인 작업은 보존하기 위해서다.

## 2026-09-25 — 7일·30일 품질 기준선 Regression Guard 도입

상태: 도입

자동 롤백은 보수적으로 수행한다. 7일·30일 모두 의미 있게 악화되고 리서치 품질도 함께 하락하며 충분한 표본과 경로 안전성이 확보될 때만 기능 단위 복원을 허용한다.

30일 기준선이 없거나 원인 귀속이 불확실하면 삭제 대신 quarantine을 우선한다.

## 2026-09-25 — Toss-first Provider Chain과 20시 NXT 실시간 경로

상태: 도입

결정: 시장 데이터의 신규 1순위 공급자를 Toss Open API 기반 고정 IP Collector로 전환한다. 신선한 Toss snapshot이 있으면 우선 사용하고 KRX 정규장에 Toss 데이터가 없을 때만 키움을 fallback으로 사용한다.

이유: 국내 WebSocket 통합 체결을 이용하면 KRX 이후 NXT 애프터마켓까지 실제 체결가×체결량 기반 1분 거래대금을 만들 수 있기 때문이다.

안전장치: KRX 종료 뒤 Toss 데이터가 없으면 NXT 값을 추측하지 않고 unavailable 상태로 기록한다.

## 2026-09-25 — 실시간 Provider snapshot은 Git 이력이 아니라 런타임 데이터로 취급

상태: 도입

결정: `data/providers/toss/latest.json`은 Git ignore 처리하고 분석 결과·통계·상태 변화만 Git에 남긴다.

이유: 초단기 raw snapshot을 Git에 누적하면 저장소가 빠르게 비대해지고 장기 연구 이력의 신호대잡음비가 나빠진다.

운영: self-hosted runner가 로컬 snapshot을 직접 읽거나 GitHub-hosted runner가 인증 HTTPS endpoint에서 매 Tick 최신 snapshot만 가져온다.

## 2026-09-25 — Market Regime도 의미 상태가 바뀔 때만 AI 호출

상태: 도입

이유: 시장이 사실상 같은데 같은 설명을 반복 생성하는 비용과 문서 중복을 줄이기 위해서다.

## 2026-09-25 — 자기진화를 폐쇄형 학습 루프로 전환

상태: 도입

발견: 기존 구조는 변경 manifest와 Regression Guard는 있었지만, 성공한 변경의 사후 평가 결과가 실험 기억으로 자동 환류되지 않아 변경과 학습 사이가 완전히 닫혀 있지 않았다.

결정: 모든 자동 변경을 검증 가능한 실험으로 취급하고, Regression Guard가 충분한 사후 표본으로 평가를 마치면 유지·격리·롤백 결과와 배운 점을 실험 기록에 자동 저장한다. Evolution Scout는 이 기록을 다음 개선 판단의 입력으로 사용한다.

학습 사이클: 관측 → 가설 → 최소 변경 → 즉시 테스트 → 운영 관측 → 사후 품질 평가 → 유지/격리/롤백 → 학습 기록 → 다음 가설.

이유: 단순 반복 자동화가 아니라 시간이 지날수록 성공/실패 경험을 축적해 같은 실수를 줄이고 검증된 접근을 재사용하는 자기진화 구조를 만들기 위해서다.

안전장치: 코드가 실행됐다는 이유만으로 성공으로 간주하지 않는다. 충분한 사후 표본과 품질 지표가 모이기 전에는 학습 결론을 확정하지 않는다.


## 2026-09-26 — NASDAQ·KOSPI 지수 대비 상대강도 보드

상태: 도입

사용자 요구: 단순 상승률 순위가 아니라 NASDAQ과 KOSPI 각각에서 기준지수보다 실제로 강한 종목과 약한 종목을 한 화면에서 비교한다.

결정: 최신 세션의 종목 등락률에서 같은 시장 기준지수 등락률을 뺀 값을 상대강도(%p)로 사용한다. 기본 유니버스는 NASDAQ 상장 시가총액 상위 500개와 KOSPI 시가총액 상위 500개이며, 상대강도 상·하위 50개와 전체 분포·지수 상회/하회 종목 수를 함께 표시한다.

이유: 지수가 +3%인 날 +1% 오른 종목과 지수가 -3%인 날 -1% 내린 종목을 같은 '상승/하락' 기준으로 보면 실제 시장 내 강약을 놓칠 수 있기 때문이다.

데이터 원칙: NASDAQ은 Nasdaq 공개 시세 화면/API, KOSPI는 Naver Finance 공개 시세를 사용한다. 조회 실패 시 임의 수치를 만들지 않고 이전 정상값은 stale, 최초 실패는 unavailable로 표시한다. 6분 센서가 실행되더라도 외부 요청을 과도하게 반복하지 않도록 상대강도 수집에는 30분 캐시를 둔다.
