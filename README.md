# Stock AutoResearch

**시장을 계속 관찰하고, 중요한 이슈를 추적하고, 두 AI가 서로 반증하며 스스로 개선하는 시장 리서치 시스템**

Stock AutoResearch는 **한국 주식 단기 매매와 시장 리서치를 위한 자동 연구·감시 프로젝트**입니다.  
10분마다 시장·뉴스·공시·리스크·데이터 상태를 관찰하고, Supervisor A와 B가 서로 다른 역할로 분석과 검증을 이어갑니다. 이슈는 단순 뉴스 목록으로 소비하지 않고 **등장 → 관찰 → 진행 → 강화 → 완화 → 해소** 흐름으로 장기간 추적합니다.

> 이 프로젝트는 자동매매 시스템이 아닙니다. 자동 주문·매수·매도는 수행하지 않으며, 시장 감시·리서치·리스크 파악과 매매 전 판단 보조를 목적으로 합니다.

## 무엇을 해결하려는가

이 프로젝트의 목표는 **데이터를 가장 많이 보여주는 것**이 아닙니다.

사용자가 화면을 열었을 때 몇 초 안에 다음을 이해하는 것이 목표입니다.

**지금 무슨 일이 벌어지고 있는가**
→ **왜 중요한가**
→ **무엇이 다음 변동의 트리거가 될 수 있는가**
→ **더 깊게 조사한 내용은 무엇인가**
→ **실제 시장 데이터는 어떻게 반응하는가**
→ **다음에 무엇을 확인해야 하는가**

전체 연구 흐름은 다음과 같습니다.

`시장 관찰 → 뉴스·이슈 발견 → 중요도 판단 → 이슈 추적 → 심층 리서치 → 시장 전달경로 분석 → A/B 상호 검증 → 다음 확인 → 프로젝트 자체 개선`

## 전체 구조

```text
시장 · 뉴스 · 공시 · 매크로 · 수급
                 │
                 ▼
       10분 비AI 센서
 :00 · :10 · :20 · :30 · :40 · :50
                 │
                 ▼
       관측 데이터 · 뉴스 탐색
                 │
        ┌────────┴────────┐
        │                 │
        ▼                 ▼
 Supervisor A (:00)   Supervisor B (:30)
 탐색 · 확장 · 개발    반증 · 검증 · 단순화
        │                 │
        └──── 상호 피드백 ─┘
                 │
                 ▼
        정규 결과 적용
                 │
       ┌─────────┼─────────┐
       ▼         ▼         ▼
   이슈 추적   장기 기억   Telegram
       │
       ├── 심층 리서치
       └── GitHub Pages

Recovery / heartbeat / self-chain
→ 센서·Supervisor 공백과 지연을 감시하고 연속성을 복구
```

10분 센서는 판단자가 아니라 **시장과 시스템의 눈**입니다.  
시장 해석, 가설, 반증, 리서치, 프로젝트 개선 판단은 A/B Supervisor가 담당합니다.

## 핵심 기능

### 이슈 추적

뉴스를 기사 단위로 나열하지 않고 **사건 단위 이슈**로 관리합니다.

- 신규 · 관찰 · 진행 중 · 강화 · 완화 · 해소 상태 추적
- 왜 시장에 중요한지
- 시장 반영 정도
- 관련 시장·섹터·자산
- 시장 전달 경로
- 확인된 사실과 미확인 내용
- 다음 확인 이벤트
- 상태 변경 이력
- 원문·공식 자료

같은 사건의 사전 일정, 발표, 후속 보도, 정책 변화는 가능한 한 같은 이슈에 누적합니다.

또한 **기사 수와 독립적인 근거 수를 같은 것으로 보지 않습니다.** 같은 원기사를 여러 매체가 재전송한 경우 기사 숫자만으로 신뢰도를 과대평가하지 않고, 핵심 사건은 공식자료·원기사·독립 출처로 다시 확인합니다.

### 리서치

리서치는 이슈 추적과 분리된 문서함이 아니라 다음 단계입니다.

`이슈 발견 → 추적 → 추가 조사 → 심층 리서치 → 시장 전달경로 → 반론 → 다음 확인`

현재 리서치 화면은 실제 저장 구조를 바탕으로 다음을 연결합니다.

- AI 심층 리서치
- 시장 이슈 연계 분석
- 증권사 리포트
- 전자공시(DART)
- 프로젝트 내부 리포트
- 관련 원문·공식 자료

### 시장 데이터

국내시장에서는 지수, 수급, 거래대금, 장후반 흐름과 최근 거래일 데이터를 봅니다.

상대강도 화면은 **Nasdaq 대비 미국 종목**, **KOSPI 대비 국내 종목**의 강약을 비교합니다. 거대자금 화면은 예탁금·신용·펀드·실제 매수 주체 등 시장의 큰 유동성 흐름을 따로 봅니다.

휴장·수집 지연·실시간 값 부재 시 과거값을 현재값처럼 가장하지 않고 최근 실제 거래일 또는 미확인 상태로 구분합니다.

### 글로벌 리스크

미국시장, 금리, 환율, 원자재와 예정 이벤트를 종합해 종가베팅 이후 발생할 수 있는 위험을 추적합니다.

리스크 개수보다 **가장 큰 단일 충격과 실제 전달 경로**를 더 중요하게 봅니다.

## Supervisor A / B

두 Supervisor는 같은 답을 반복하도록 만든 구조가 아닙니다.

### A · 탐색 / 확장 / 개발

A는 새로운 가능성을 넓게 찾습니다.

- 새로운 시장 이슈와 가설
- 데이터 이상과 누락
- 추가 리서치 방향
- 필요한 기능·데이터
- UI/UX 개선 후보
- 안전한 코드 개선

### B · 반증 / 검증 / 단순화

B는 A의 판단을 그대로 받아들이지 않습니다.

- 근거 부족과 반대 자료 확인
- 중복·재전송 뉴스 검증
- 잘못된 시장 해석 반증
- 코드 변경의 부작용 확인
- 불필요한 기능과 UI 복잡성 제거
- 실제 효용이 없는 개선안 보류

A와 B의 의견이 다르면 한쪽 판단을 지우지 않고 **의견 차이와 필요한 추가 증거**를 남겨 다음 관측으로 다시 검증합니다.

### 고정 3슬롯 관측 원칙

A와 B는 임의의 “최근 3개” 관측을 사용하지 않습니다.

- **A(:00)** → 직전 `:40` · `:50` · 현재 `:00`
- **B(:30)** → 현재 `:10` · `:20` · `:30`

예상 슬롯이 3개인데 실제 데이터가 2개뿐이면 **2/3을 3/3처럼 만들지 않습니다.** 누락된 슬롯을 더 오래된 데이터로 조용히 채우지 않고 검증 대기 상태를 유지합니다.

## 10분 센서

`.github/workflows/연속연구와진화.yml`은 매 10분 슬롯의 사실 관측을 담당합니다.

주요 관측 범위는 다음과 같습니다.

- 국내시장 공개 배치 데이터
- 연결된 Toss 시장 데이터
- 상대강도
- 뉴스·공시 탐색
- 시장·리스크 런타임
- 데이터 공급자 상태
- Health
- Regression
- 거대자금
- Supervisor 관측 큐

센서 자체는 AI 판단을 하지 않습니다.

### 연속성 보조망

GitHub 예약 실행만 믿지 않습니다.

1. **self-chain** — 센서가 끝날 때 다음 10분 슬롯을 연결
2. **GitHub schedule** — 기본 예약 실행
3. **10분 heartbeat** — 현재 슬롯이 빠졌을 때만 보조 실행
4. **Recovery** — 장시간 stale·누락·운영 이상 감지

오래 지연된 실행을 과거 슬롯의 실제 관측처럼 저장하지 않고 현재 정규 10분 슬롯으로 재기준화합니다.

## Recovery

Recovery는 A/B와 경쟁해서 별도의 시장 결론을 만드는 역할이 아닙니다.

주요 목적은 다음과 같습니다.

- 10분 센서 누락 감지
- 뉴스 탐색·Pages·운영상태 stale 감지
- 필요한 센서 재실행
- A/B 결과 공백 확인
- 장기 기억과 운영 상태 갱신
- 정상 데이터와 복구 데이터를 구분

Recovery 결과가 존재하더라도 정규 A/B 관측 구간을 임의로 전진시키지 않도록 별도 규칙을 둡니다.

## 장기 기억

`memory/`는 로그 저장소가 아니라 **AI가 이전 판단과 시행착오를 이어받기 위한 장기 기억 계층**입니다.

```text
memory/
├─ INDEX.md             빠른 진입점
├─ current/             현재 상태 · 열린 문제 · 가설 · 다음 확인
├─ market/              시장 이슈 · 시장 반응
├─ research/            질문 · 가설 · 반증 · 발견
├─ project/             기능 · 공급자 · 설계 · 실패 기록
├─ lessons/             재사용할 교훈
├─ supervisors/         A/B/Recovery 실행 기록
└─ snapshots/           일·주·월 단위 압축 기억
```

원칙은 **기록은 풍부하게, 시작할 때 읽는 기억은 작게, 필요할 때 깊게 검색**하는 것입니다.

## 자기진화

A/B Supervisor는 시장만 분석하지 않고 프로젝트 자체도 계속 검토합니다.

- 데이터가 제대로 들어오는가
- 중요한 뉴스가 빠지고 있지 않은가
- 같은 오탐과 중복이 반복되는가
- 새로운 시장 데이터가 필요한가
- 버그나 파서 변화가 있는가
- UI에서 핵심이 아래에 묻히는가
- 비슷한 카드와 기능이 중복되는가
- 새 기능이 실제로 도움이 되는가
- 기존 기능을 통합·단순화·삭제하는 편이 나은가

성과 기준은 **기능을 몇 개 추가했는가**가 아닙니다.

> 사용자가 현재 시장을 더 빠르고 정확하게 이해하게 되었는가?

## GitHub Pages

Pages의 기본 정보 우선순위는 다음과 같습니다.

`시장 영향 이슈 → 다음 변동 트리거 → 심층 리서치 → 시장 데이터·보조 분석 → 시스템 상태 → AI 협업 과정`

- **시장 홈** — 현재 시장 해설, 핵심 이슈, 다음 트리거, 주목 리서치
- **이슈 추적** — 사건의 등장부터 강화·완화·해소까지 추적
- **리서치** — 중요 이슈의 심층 분석과 공식 자료
- **국내시장** — 국내 지수·수급·거래대금·시장 상태
- **글로벌 리스크** — 해외시장·금리·환율·원자재·예정 이벤트
- **상대강도** — 지수보다 강한 종목과 약한 종목
- **거대자금** — 시장 전체 유동성과 큰 자금 흐름
- **시스템** — 공급자·Health·Regression·Recovery
- **AI 대화** — A/B/Recovery의 실제 저장 결과를 시간순으로 확인

### AI 대화는 가짜 채팅이 아닙니다

`AI 대화` 페이지는 `data/supervisor/ai-results/*.json`의 실제 구조화 결과를 사용합니다.

`A 발견 → B 반론 → A 수정 → B 재검증`

흐름뿐 아니라

`센서 문제 발견 → 구조 개선 → 후속 반증 → 재수정`

같은 프로젝트 자기진화 과정도 볼 수 있습니다.

## 데이터 신뢰성 원칙

- 빈 값을 정상값처럼 해석하지 않습니다.
- 없는 숫자나 시장 상태를 임의로 만들지 않습니다.
- 누락 슬롯을 오래된 관측으로 채워 정상처럼 보이게 하지 않습니다.
- 기사 재전송과 독립적인 근거를 구분합니다.
- 공시·거래소·정부·기업 IR 등 1차 자료를 우선합니다.
- 확인된 사실, 당사자 주장, 분석, 추정, 미확인을 구분합니다.
- 휴장일에는 오래된 실시간값을 현재값처럼 보여주지 않습니다.
- stale 데이터는 갱신 지연 또는 확인 필요 상태로 표시합니다.
- 공급자 보조값을 사용할 때 출처와 정확값·추정값 구분을 보존합니다.
- 성공 사례만 골라 연구 통계를 만들지 않습니다.

## 데이터 공급 구조

국내시장 데이터는 한 공급자만 믿지 않습니다.

- 네이버 공개 10분 배치
- Toss 고정 IP Collector 및 저장된 snapshot
- 읽기 전용 시장 데이터 보조 경로
- DART·뉴스·공식자료 탐색
- 공급자 간 누락·지연 검사

Toss 수집은 현재 Top50만 보고 끝내지 않고, 당일 한 번이라도 추적 대상에 들어온 종목의 연속성을 유지하는 구조를 사용합니다.

세부 정의와 exact/estimated 구분은 [시장데이터 명세](docs/시장데이터_명세.md), Toss 설정은 [고정 IP Toss 10분 러너](docs/고정IP_토스_러너.md)를 참고합니다.

## 현재 동작 / 개선 중 / 장기 목표

### 현재 동작

- 10분 비AI 관측과 고정 슬롯 큐
- 뉴스·공시·시장 데이터 탐색
- A/B 상호 피드백과 정규 결과 적용
- 이슈 생명주기와 리서치
- 장기 기억
- Health · Regression
- GitHub Pages 자동 배포
- Supervisor 결과 Telegram 알림 경로
- 상대강도·거대자금·글로벌 리스크 화면

### 개선 중

정상 동작 여부를 단순히 “워크플로가 성공했는가”만으로 판단하지 않습니다. 데이터 공급자 저하, 뉴스 이슈 원장 갱신, 정규 A/B 연속성, macro 실데이터 공백처럼 실제 결과 품질에 영향을 주는 문제는 `verification_pending` 상태로 남겨 후속 관측에서 다시 확인합니다.

현재 시점의 구체적인 미완료 항목은 [시스템 페이지](https://juhwan7.github.io/stock-autoresearch/시스템.html), [AI 대화](https://juhwan7.github.io/stock-autoresearch/AI대화.html), `memory/current/`를 기준으로 확인합니다.

### 장기 목표

- 사용자 개입 없이 장기간 안정적으로 운영되는 시장 연구 시스템
- 더 넓은 원자료·공식자료 커버리지
- 질문 → 가설 → 반증 → 사후검증의 장기 품질 학습
- 시장 변화에 따라 데이터·리서치·UI를 함께 개선하는 자기진화
- 기능 수가 아니라 실제 시장 이해 속도와 정확도로 개선 효과 평가

## 검증

Python 3.11+ 환경을 기준으로 합니다.

```bash
pip install -e ".[dev]"

python -m compileall -q src collector scripts
pytest -q

python -m autoresearch run --mode dry-run
python -m autoresearch evolve --mode dry-run
python -m autoresearch market-intel --mode dry-run
python -m autoresearch risk-intel --mode dry-run

python -m autoresearch health
python -m autoresearch regression
python scripts/대시보드_생성.py
git diff --check
```

GitHub Actions의 `프로젝트 검증`도 같은 핵심 경로를 실행합니다.

## 주의사항

Stock AutoResearch는 시장 판단을 돕는 연구 도구입니다.

- 자동 주문·자동 매수·자동 매도를 수행하지 않습니다.
- 특정 종목의 매수·매도를 자동 결정하는 시스템이 아닙니다.
- 실시간 데이터가 없을 때 추측으로 숫자를 만들지 않습니다.
- Secret·토큰·인증정보를 저장소와 로그에 기록하지 않습니다.
- 외부 서비스 권한이 필요한 변경은 최소 권한 원칙을 사용합니다.

최종 투자 판단과 주문은 사용자가 직접 수행합니다.
