# 재사용 가능한 교훈

> 반복해서 다른 사이클에도 적용할 가치가 있는 교훈만 기록한다.

## GitHub 동시 변경

- 증상: AI 수정 중 다른 workflow가 main을 갱신하면 SHA conflict가 발생할 수 있다.
- 대응: 수정 직전 최신 파일/SHA를 다시 읽고, 큰 변경은 작은 독립 커밋으로 나눈다.
- 원칙: 오래된 생성 데이터를 억지로 병합하기보다 다음 관측에서 최신 입력으로 재생성하는 편이 안전한 경우가 있다.


## Supervisor 결과 쓰기 실패와 예약 중단

- 증상: canonical 센서 window는 정상인데 regular A/B result가 비고, 상대 Supervisor가 계속 같은 공백을 관측한다.
- 실제 원인 후보를 분리한다: automation disabled, schedule missed, result write failed, canonical apply failed. complete window만 보고 원인을 하나로 단정하지 않는다.
- 금지: connector `create_file` 한 번 차단 → Supervisor `is_enabled=false`.
- 검증된 복구: direct write가 막히면 `[Supervisor Result] Issue → Action single-writer`를 우선하고 결과 파일·canonical·memory·Telegram을 재조회한다.
- 불변식: recoverable failure에서는 `disable_supervisor=false`. 살아 있는 A/B가 상대 예약을 확인해 기존 스케줄 그대로 재활성화한다.
- 반복 패턴: 같은 connector write 차단이 다시 나오면 원인 조사부터 반복하지 말고 검증된 single-writer fallback을 먼저 사용한다.
- 저장 위치: `data/supervisor/collaboration.json.failure_patterns`에 반복 원인별 `occurrences`, `preferred_recovery`, `disable_supervisor=false`, 마지막 검증 batch/시각을 남긴다. 같은 batch의 idempotent 재적용은 장애 횟수를 늘리지 않는다.
